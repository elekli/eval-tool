# eval-tool Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local web LLM-eval tool (OpenRouter-native) that runs two one-shot eval types — prompt-behaviour eval with an LLM-as-judge, and model-layer tool-use selection eval — and shows results summary-first then drill-down.

**Architecture:** A framework-agnostic `core/` (pure TypeScript: types, storage, runner, judge, metrics, generator, job orchestration) with no Next.js imports, wrapped by a thin Next.js App Router `app/` layer (REST + SSE) and a React UI. Eval execution is modelled as a DB-persisted job so progress survives request lifecycle. Four seams (storage interface, persisted job, `owner_id`, Runner interface) are in place so hosting/harness extensions are additive.

**Tech Stack:** TypeScript (strict), pnpm, Next.js 15 (App Router), React, `better-sqlite3`, OpenRouter via `fetch` (OpenAI-compatible endpoint), Ajv, Vitest + MSW + Testing Library, Recharts.

**Spec:** `docs/superpowers/specs/2026-06-17-eval-tool-design.md` — read it before starting.

- [ ] **Step 4: Implement SQLiteRepo**

Implement `core/storage/sqlite-repo.ts`: constructor runs the DDL via `db.exec(SCHEMA_SQL)`, where `SCHEMA_SQL` is an exported const in `core/storage/schema.ts` (single source of truth). **Do NOT read a `.sql` file via `readFileSync(new URL(..., import.meta.url))`** — a `.sql` asset does not survive the Next.js/webpack server bundle, so it would break the moment an API route instantiates the repo (Chunk 7). A `.ts` const is bundler-safe and still a single source. Each method maps row ⇄ domain object, `JSON.parse/stringify` for the JSON columns. For writers, use `?? null` for optional (`?`) fields and `!== null` only for genuine `| null` fields (e.g. `judge`) — avoid truthiness checks that would coerce a falsy-but-valid value to NULL. `createDataset(d, cases)` inserts the dataset row then each case in a transaction (no `created_at` on `test_cases`). Provide private `rowToSuite`, `rowToRun`, `rowToResult`, `rowToTestCase` helpers. Use prepared statements. Tests must also assert **absent optional fields round-trip back as `undefined`/`null`** (insert a minimal `error` result with no optionals; a suite with `judge: null`; a dataset without `genSpec`).
